# ADR-001 · Arquitectura del agente "Registro como Proveedor"

- **Estado:** aceptado (2026-11-10)
- **Contexto:** PRD Reto 01 + lista de errores a evitar del proceso de evaluación (confirmación ligada a hash/versión y atómica, FK a usuarios, carreras entre sesiones, plantillas preservadas, datos bancarios fuera del LLM).

## Decisión

| Tema | Decisión | Alternativa descartada | Por qué |
|---|---|---|---|
| Runtime | Node 20 + TypeScript estricto (`noUncheckedIndexedAccess`), `tsx` sin paso de build | Bun | Node es el runtime por defecto de los evaluadores y de la CI |
| LLM | Interfaz propia `LlmAdapter.enviar(system, mensajes, herramientas)`; Anthropic (modelo configurable) + **simulado determinista** | SDK acoplado al ciclo | Cambiar de proveedor no toca el ciclo; las pruebas y la CI corren sin clave |
| Persistencia | **Postgres** (Docker/Render) y **PGlite** (Postgres en WASM) para local y `npm test` | SQLite; archivos JSON | Mismo dialecto SQL en ambos; FK, UNIQUE, `FOR UPDATE` y transacciones reales; la clave de idempotencia sobrevive a varias réplicas |
| Concurrencia | Bloqueo optimista (`version`) en cada transición + `UNIQUE(caso)` + lease de sesión en BD | Mutex en memoria | El estado en memoria no protege entre procesos o réplicas |
| HITL | Token de un solo uso emitido por el servidor, ligado a `payload_hash`, versión, usuario, sesión y expiración; consumo compare-and-set en una transacción; el token va solo al front | Confirmar por texto libre ("sí, envía") interpretado por el LLM | El LLM no debe poder producir la confirmación; un texto no prueba qué versión vio el humano |
| Privacidad | Vistas minimizadas en las herramientas + guarda de salida (`PrivacyGuardAdapter`) | Confiar en el prompt | Defensa en profundidad comprobable con un espía |
| Documentos | Cargar la plantilla (original del cliente si existe) y escribir solo celdas/campos de valor; AcroForm en PDF | Regenerar el archivo | Preserva el formato del cliente; verificable celda a celda |
| Mapeo | Determinista: glosario → similitud léxica (≥0.8 lleno; 0.5–0.8 confirmar) → faltante | Mapeo por LLM | El valor nunca depende del modelo; trazable a una ruta del maestro |

## Responsabilidades

| LLM | Código determinista |
|---|---|
| Entender la petición, elegir herramientas, redactar el resumen y la pregunta de cierre | Lectura y validación de fixtures, mapeo, vigencias, generación de xlsx/pdf/md, paquete y hash, tokens, CAS, idempotencia, authz, auditoría y alertas |

## Consecuencias

- (+) Cada error de la lista tiene control y prueba automatizada (`anti_error_1_*`).
- (+) `npm test` reproducible sin clave ni Docker; la CI además prueba contra Postgres 16.
- (−) Más piezas que el mínimo del PRD (usuarios, BD). Se justifica por los criterios de evaluación.
- (−) El envío exige un clic en la UI. Un cliente API debe usar `POST /api/confirmaciones`.
